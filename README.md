# hv86

Гипервизор «по смыслу как Hyper-V», но виртуальные машины исполняет
[v86](https://github.com/copy/v86) — x86-эмулятор, скомпилированный в WebAssembly.
Управляющая часть, служба Windows, окна, снапшоты и отказоустойчивость — на C# и WebView2.

```
 hv86.exe  ──►  менеджер (Hyper-V-подобное окно, WebView2)
              └► служба Windows  ──►  vmhost на каждую ВМ (v86 в WebView2)
```

## Что уже работает

- **Служба Windows**: установка/удаление/автозапуск, лог, переживает перезапуск.
- **Менеджер**: дерево хоста и ВМ, таблица состояний, панель действий, журнал событий,
  визард создания ВМ, контекстное меню, горячие клавиши (F5/F6/F2/Enter/Del), RU/EN.
- **Настройки ВМ**: имя, память, автозапуск, режим/интервал/глубина чекпоинтов,
  политика рестарта и лимит попыток — всё без правки `vm.json`.
- **Клон, экспорт/импорт `.hv86x`** (zip: описание + диски + медиа) и **диагностика**
  одним архивом (логи + описания ВМ + окружение).
- **Проброс TCP-портов** host → guest: `127.0.0.1:2222 → guest:22`; правила в
  настройках ВМ, применяются на лету, всё видно в журнале.
- **Консоль ВМ** отдельным окном: экран v86, клавиатура/мышь, пауза, сброс, вставка
  ISO/образа «на горячую», снапшот, скриншот, скрытие окна (ВМ продолжает работать).
- **Снапшоты**: снять на работающей ВМ, откатить (возвращается и состояние, и диск),
  удалить; у каждого — своя копия образа диска.
- **Динамическая отказоустойчивость**: кольцо чекпоинтов по таймеру, heartbeat,
  watchdog; упавший `vmhost` поднимается сам, ВМ восстанавливается из свежего
  чекпоинта, счётчик рестартов и события — в UI.
- **Диски**: raw-образы (sparse), изменения гостя сохраняются на диск при штатной
  остановке; при падении образ остаётся целым, ВМ откатывается к чекпоинту.
- **Пресеты**: FreeDOS, KolibriOS, Oberon, TinyCore, Linux — скачивание с проверкой SHA-256.

## Быстрый старт

```bat
tools\build.cmd                 :: сборка (+ скачивание WebView2 SDK и v86)
bin\hv86.exe --service install   :: установить службу (нужны права администратора)
bin\hv86.exe --service start
bin\hv86.exe                     :: открыть менеджер
```

В менеджере: **Новая ВМ…** → пресет `FreeDOS 7.22` → **Создать** → **Подключиться**.
FreeDOS грузится за секунду. Дальше — **Сделать снапшот…**, **Вставить ISO…**, **Перезагрузить**.

Без установки службы (отладка, портативный режим):

```bat
dotnet bin\hv86.dll --engine     :: движок в консоли, интерфейс подключается к нему
dotnet bin\hv86.dll             :: менеджер
```

## Управление из консоли

Тот же движок, что и у менеджера, доступен из командной строки — через тот же
named pipe, поэтому состояние всегда одно:

```bat
hv86 --cli status
hv86 --cli list
hv86 --cli create --name dev --preset tinycore --memory 256 --disk 256
hv86 --cli start dev
hv86 --cli snapshot dev before-update
hv86 --cli snapshots dev
hv86 --cli revert dev 0001-before-update
hv86 --cli stop dev
hv86 --cli export dev D:\backup\dev.hv86x
hv86 --cli import D:\backup\dev.hv86x
hv86 --cli diagnostics
```

`<vm>` — id, его префикс или имя. Флаг `--json` печатает машинный вывод для скриптов,
коды возврата: `0` — успех, `1` — ошибка, `2` — неверные аргументы.

## Проверка

```powershell
tools\selftest.ps1              # сборка + unit + selftest + реальная загрузка + itest
tools\selftest.ps1 -SkipItest   # без сценария со службой
```

Что именно проверяется:

| команда | что делает |
|---|---|
| `--unit` | формат state-файла v86, применение блоков диска, JSON, пути |
| `--selftest` | вшитые ресурсы, WebView2 Runtime, каталог данных, каталог пресетов, служба |
| `--smoke <образ>` | настоящая загрузка гостя → `save_state` → перезапуск из state |
| `--itest` | движок + vmhost: создать → загрузить → снапшот → убить vmhost → автоподъём → откат → удалить |

## Честные ограничения

- v86 — **32-битная** машина без SMP: Linux i386, DOS, Win 9x/2000 — да;
  современные 64-битные гости — нет.
- Скорость — единицы-десятки MIPS: это эмулятор, а не KVM.
- `vmhost` — процесс WebView2, поэтому ВМ живут в сессии пользователя.
  Headless-движок (работа без входа в систему) — следующий этап, M5.
- Снапшот содержит копию диска: место на диске = состояние + образ.
- При аварийном падении изменения гостя на диске не сохраняются — ВМ откатывается
  к чекпоинту (сохранение диска делается при штатной остановке).
- Один хост, без живой миграции и реплики на вторую машину (M6).
