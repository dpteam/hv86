# Headless-движок: v86 под Node

Документ про `engine/vmhost.mjs` и `VmHost/…`-часть, которая с ним говорит.

## Зачем

Главное ограничение гипервизора на v86: `WebView2` не работает в сессии 0,
поэтому ВМ живут в сессии пользователя и умирают при логауте. Headless-движок
снимает это: v86 исполняется в Node, который спокойно живёт под службой.

## Что он умеет и чего нет

| | web (WebView2) | headless (Node) |
|---|---|---|
| графика | да (canvas, мышь, звук) | **нет** — только VGA-текст |
| окно | своё окно v86 | окно рисует интерфейс по тексту |
| сессия | пользовательская | **сессия службы (0)** |
| работа без логина | нет | **да** |
| снапшоты/чекпоинты | да | да (тот же state) |
| проброс портов | да (fetch-стек) | нет (нет страницы) |
| релей (TCP наружу) | да (`net.mode=relay`) | нет (в v1) |

Почему нет графики — см. ниже, это осознанно.

## Протокол

Один и тот же, что у `hv86.exe --vmhost`: named pipe `\\.\pipe\hv86-vm-<id>`,
построчный JSON-RPC, события `{event, data}`. Поэтому служба, снапшоты,
watchdog и UI не знают, какой движок внутри:

- `vm.status` → state, instructions, mips, engine
- `vm.pause/resume/reset`
- `vm.saveState {path}` → Node пишет файл напрямую через `fs` (без кусков base64,
  как в WebView2 — там иначе нельзя)
- `vm.key {text|scancodes}` — ввод
- `vm.screen` + событие `vm.screen` — 80×25 строк с ANSI-цветами
- `vm.mount/eject`, `vm.shutdown`

## Почему текст, а не картинка

В браузере v86 рисует через свой `ScreenAdapter`: canvas, `putImageData`,
`OffscreenCanvas`, `requestAnimationFrame`, разметка текстового слоя. В Node
всего этого нет, и v86 подставляет «пустой» адаптер с текстовым буфером.

Пути получить пиксели:

1. **Шим DOM+Canvas** (фейковые `document`, `ImageData`, callback'и). Технически
   возможно, но это эмуляция браузера внутри эмулятора x86 — хрупко: минифицированный
   адаптер завязан на layout, `getBoundingClientRect`, `devicePixelRatio` и порядок
   вызовов. Ломается при каждом обновлении v86.
2. **Патч libv86.js** — прямое нарушение правила «не патчим v86».
3. **Текст** (выбрано): v86 с `screen: {ansi:true}` отдаёт `get_text_screen()` —
   готовые строки с truecolor-кодами. Этого достаточно Linux-консоли и DOS.

Отсюда правило: гость с GUI (KolibriOS, Win9x, ReactOS) — на web-движке;
консольный гость (Linux server, DOS) — можно headless.

## Как устроен процесс

- `node engine/vmhost.mjs --config <json>`; конфиг (пути к BIOS/wasm/образам)
  собирает C# и кладёт в `vms\<id>\temp\boot-*.json`. Дублировать разбор
  `vm.json` в JS не нужно.
- BIOS и wasm вшиты в exe, а Node их не читает из ресурсов — `Vm/V86Assets`
  выкладывает `seabios.bin`, `vgabios.bin`, `v86.wasm` в
  `%ProgramData%\hv86\cache\v86\<версия>\`.
- `NodeRuntime` ищет node.exe: `HV86_NODE` → PATH → Program Files → `engine\node`.
  Требуется Node 20+.
- Пакет `v86` ставится в `engine\node_modules` (`tools\fetch-engine.ps1`),
  версия пиннится в `engine\package.json`.

## Сохранение диска

В `save_state()` попадают только изменённые блоки диска (по 256 байт). Web-движок
отдаёт state в C#, и там `Vm/V86State` применяет блоки к образу. В Node state
и так под рукой, поэтому разбор (заголовок → JSON `buffer_infos` → буферы)
сделан в `applyDiskBlocks()` того же файла — 60 строк и никаких лишних передач.

## Ввод

Текст — `keyboard_send_text` (раскладка US), спецклавиши — скан-кодами PS/2
(`keyboard_send_scancodes`). Мышь не поддерживается: в headless её некому
превращать в пакеты PS/2, а для консоли она не нужна.

## Как проверяется

`hv86 --htest`: поднимает движок в процессе, создаёт ВМ `engine=headless`,
ждёт в VGA-тексте `FreeDOS`/`A:\>`, открывает и закрывает окно консоли (проверка
подключения и отрисовки), снимает снапшот, останавливает и удаляет.
Если Node или `engine\node_modules` нет — код возврата 3 и понятный текст,
поэтому шаг в `tools\selftest.ps1` пропускается честно, а не «зелёным».
