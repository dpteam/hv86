# Шрифты текстового режима

Шрифт влияет только на отрисовку на хосте: гость про него ничего не знает и
своих шрифтов не отдаёт.

## Откуда берутся

1. **Системные** — из реестра `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Fonts`
   (`FontCatalog.SystemFonts`). Список живой: поставили шрифт в Windows — он
   появился в hv86.
2. **Загруженные пользователем** — файлы в `%HV86_ROOT%\fonts`, описание в
   `hv86.json` → `fonts: [{family, file}]`.

Имя семейства берётся **из самого файла** (таблица `name`, nameID 1 или 16, с
приоритетом типографского имени и платформы Windows), а не из имени файла:
`consola.ttf` — это семейство `Consolas`, и в CSS нужно именно второе. Если
разобрать не удалось, используется имя файла: шрифт всё равно применится.

Поддержаны `.ttf`, `.otf`, `.ttc` (коллекция — берётся первый шрифт).

## Как попадает в страницу

- Список — через `host.fonts` (RPC) и push-событие `fonts`.
- Файл — по `https://hv86.local/font/<файл>` из ресурсного сервера vmhost
  (только имя файла, без путей: выйти из каталога шрифтов нельзя).
- В консоли файл подключается через `FontFace` API, поэтому работает и в CSS,
  и в canvas-отрисовке v86.

## Настройки

- Хост: шрифт по умолчанию и размер (0 — 14 px).
- ВМ: свой шрифт и размер; пусто — как на хосте.

Применяется при следующем запуске консоли: страница получает шрифт в
boot-конфиге.

## Почему не «просто font-family»

Текстовый слой — это `<div>` с построчным текстом, поэтому шрифт задаётся CSS.
Но размер и `line-height` обязаны ставиться всегда: слой наследует
межстрочный интервал контейнера, а там раньше был `0` — все строки
схлопывались в одну (см. `docs/screen.md`).
